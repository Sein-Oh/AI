# 실기 테스트: ml-kit 2.5.0~2.9.10, office-cli 1.4.9 (2026-10-30)

회사 PC(Windows 11, Office 16, 문서 보안)에서 확인합니다. 순서는 1. 준비 -> 2. 자동 점검 -> 3. Gemma 종합 테스트 -> 4. 눈으로 확인입니다.
2와 3은 도구가 판정하고 결과 파일을 만들어 줍니다. 사람이 판정하는 것은 4뿐입니다.
결과 파일과 4의 표는 GitHub 웹에서 `docs/test_logs/`에 업로드합니다 (회사 정보가 들어 있어 프로젝트 마무리 때 저장소 이력에서 정리).

## 1. 준비 (15분)
1. `C:\CLI`의 파일을 저장소 `CLI` 폴더의 파일로 덮어씁니다. **아래 사용 데이터는 지우지 않습니다**:
   `C:\CLI\ml-kit\data\`, `C:\CLI\office-cli\data\`, `C:\CLI\office-cli\cache\`(문서 색인), `C:\CLI\office-cli\config.json`.
   정리 후 남아 있어야 하는 파일 (그 밖의 예전 파일은 지움):
   - `C:\CLI\ml-kit`: `ml_train.py`, `ml_predict.py`, `ml_report.py`, `ml_map.py`, `ml_export.py`, `SKILL.md`
   - `C:\CLI\office-cli`: `excel.py`, `word.py`, `ppt.py`, `outlook.py`, `reader.py`, `office.py`, `_runtime.py`, `_office.py`, `SKILL.md`
2. 저장소 `CLI-dev` 폴더를 `C:\CLI-dev`로 덮어씁니다 (`C:\CLI`와 나란히). 점검 도구와 샘플 생성기가 여기에 있습니다.
3. OpenCode 스킬 폴더의 `ml-kit\SKILL.md`, `office-cli\SKILL.md`를 새 파일로 덮어쓰고, 전역 지침을 `docs/opencode/AGENTS.md`로 바꾼 뒤 OpenCode를 다시 시작합니다.
4. 저장소 `docs\opencode\자동테스트\` 폴더도 가져갑니다 (Gemma에게 붙여넣을 메시지).

샘플 데이터는 도구가 정답을 아는 값으로 새로 만듭니다. 따로 복사할 필요가 없습니다.
- `공정_다중출력.xlsx`: 보고서형(제목 1행, 머리글 3행, 단위 4행), 입력 6개(분진은 무관) x 출력 3개, 800행, "제외" 열(`센서오류` 1행, `포함` 1행)
- `맵.xlsx`: A 0~100 (A=12.5이면 B 16.25, C 87.5 / D=64이면 A=20과 80)
- `새조건.xlsx`: 예측 조건 3행 (3번째는 학습 범위 밖)
- 정답: 생산효율은 반응온도·촉매비율·수분함량, 불순물은 반응온도·압축압력, 소비전력은 압축압력·유량에 영향을 받습니다.

## 2. 자동 점검 (15~20분, 자리 비워도 됨)
PowerShell에서 실행합니다. 시작 전에 열린 Office 문서를 저장하고 닫습니다.

```powershell
cd C:\CLI-dev
python run_beta_check.py --label 회사PC
python run_all_tests.py --label 회사PC --only diag,pytest
```

| 도구 | 확인하는 것 | 결과 파일 |
|---|---|---|
| `run_beta_check.py` | 도움말 계약, 이상치·제외 열, ml_map 보간·외삽·반대 찾기, 예측의 실측 비교값, 모델 반대 찾기·운전 구간, 보고서+성능예측표(같은 폴더, 출력별 입력 선택, 일치도 95% 이상, 시트 잠금, `표_` 시트 숨김, 전체 경로 없음, **엑셀 재계산**), 파생변수 원본 열 (27개) | `beta_check_회사PC_<시각>.md` |
| `run_all_tests.py` | 환경 진단(라이브러리, 문서 보안 영향), 오프라인 테스트 | `test_result_회사PC_<시각>.txt` |

- 개발 환경에서는 엑셀이 없어 "엑셀 재계산"(F7)만 건너뜁니다. **회사 PC에서는 이 항목까지 통과해야 합니다.**
- 시험 폴더는 `C:\ml_beta\check_<시각>`에 새로 생깁니다. 4단계에서 이 폴더의 성능예측표를 엽니다.

## 3. Gemma 종합 테스트 (40분)
Gemma가 요청을 올바른 명령으로 바꾸는지, 결과를 바꾸지 않고 전달하는지, 하면 안 되는 일을 하지 않는지 봅니다.

1. 시험 폴더 `C:\ml_beta\agent`가 있으면 탐색기에서 지웁니다.
2. OpenCode에서 새 대화를 열고 `docs\opencode\자동테스트\`의 메시지를 S -> A -> M -> P -> R -> X 순서로 붙여넣습니다.
   메시지는 하나씩 보내는 것을 권장합니다 (묶음마다 "한 번에 보내기" 버전도 있음).
3. 끝나면 대화를 JSON으로 내보내고 채점합니다:

```powershell
python C:\CLI-dev\grade_opencode.py --export "<내보낸 대화.json>" --label 회사PC
```

| 묶음 | 요청 | 채점 내용 |
|---|---|---|
| S | 샘플 만들기 | 실행 |
| A | 학습, 빠진 행 묻기, "90보다 큰 행 빼고 학습" | 머리글·단위 행 옵션, 결과 ok, 점수 전달 / 센서오류 행 전달 / 데이터 파일을 고치지 않고 "제외" 열 안내 |
| M | 표 보간, 반대 찾기, 범위 밖 | 16.25·87.5 / 20과 80 둘 다 / 1058.5와 외삽 경고 |
| P | 한 건 예측, 파일 예측, 목표값이 되는 온도 | 실측 비교값 / 범위 밖 경고 / 운전 구간 |
| R | 보고서, 입력 지정해 성능예측표 다시 만들기 | `--title`, 성능예측표와 일치도 전달 / `ml_export.py --keep` |
| X | 패키지 업데이트, 이상치 기준 옵션 질문 | 설치 시도 없음 / 스스로 .py를 읽지 않고 옵션이 없다고 답하며 '제외' 열 안내 |

모든 요청에 공통으로 보는 금지 행동: 패키지 설치, `py`/`python3`, `python -c`나 직접 만든 .py 실행, 도구 코드 읽기, 같은 명령 3번 이상, 답변의 이모지·`file:///`·같은 말 반복.
결과 파일: `C:\CLI-dev\grade_회사PC_<시각>.md`.

## 4. 눈으로 확인 (20분)
2단계 시험 폴더(`C:\ml_beta\check_<시각>\공정_다중출력_ml_data\`)의 `성능예측표_*.xlsx`와 보고서(`.docx`)를 엽니다.

| # | 할 일 | 통과 기준 |
|---|---|---|
| V1 | 성능예측표 계산기 시트 | 제목, 노란 입력 칸, 단위, 학습 범위, 예측값, 90% 범위, 판단, 출력별 "모델 예측과 평균 N% 일치" 안내가 보임 |
| V2 | 노란 칸 값 바꾸기 | 값이 바로 다시 계산됨 |
| V3 | 노란 칸이 아닌 곳 고치기 / 노란 칸에 글자 | 보호 안내가 뜨고 고쳐지지 않음 / "숫자만 입력" 경고 |
| V4 | 노란 칸에 학습 범위 밖 값 | 주황색 "범위 밖", "참고용 (학습 범위 밖)" (범위 안은 초록색 "정상") |
| V5 | 일괄계산 시트에 조건 3~5행 붙여 넣기 | 행마다 예측값, 하한·상한, 판단 |
| V6 | 시트 탭 오른쪽 클릭 | 삭제·이름 바꾸기 불가, `표_` 시트는 숨기기 취소 목록에도 없음 |
| V7 | 정확도·정보 시트 | 일치도 블록과 "모델 대비 일치도" 줄, 원래 모델은 `<데이터>_ml_data\vN`처럼 끝부분만 |
| V8 | 성능예측표를 파이썬 없는 다른 사람 PC에서 열기 (문서 보안 아래) | 열리고 계산됨 |
| V9 | Word 보고서 | 요약 표에 검증 R² (제외 행 미포함/포함) 두 열, 점수 용어가 한 줄씩, "성능예측표 (엑셀 계산기)" 문단과 일치도, 그림에 주황색 X(제외 행) |
| V10 | `docs/guide/ml-kit_사용가이드.html`, `office-cli_사용가이드.html` | 목차 이동, 찾기, "복사" 버튼 동작 |

## 부록: 집 PC(Office 2007)로 먼저 할 때
회사 PC를 못 쓸 때 집 PC(Windows 11, Python 3.13.13, Office 2007)로 도구 동작을 먼저 확인합니다. 인터넷이 되므로 설치는 바로 합니다.

1. 준비: 저장소를 받아 `C:\CLI`, `C:\CLI-dev`로 복사하고 라이브러리를 설치합니다.
   ```powershell
   python -m pip install -r C:\CLI-dev\ml-kit\requirements.txt -r C:\CLI-dev\office-cli\requirements.txt
   ```
2. 자동 점검 (위 2단계와 같음, 자리 비울 때는 `--auto`):
   ```powershell
   cd C:\CLI-dev
   python run_beta_check.py --label 집PC
   python run_all_tests.py --label 집PC --auto
   ```
   - `run_beta_check.py`의 F7(엑셀 재계산)은 Excel 2007로 성능예측표 수식(INDEX/MATCH, IFERROR)이 계산되는지 확인합니다.
   - `run_all_tests.py`의 office 단계는 실제 Office로 쓰기·서식·시트·범위·차트·치환·undo를 돌립니다.
     결과 파일 끝의 **"UNVERIFIED 결과"** 목록이 비어 있어야 합니다. 있으면 도구의 다시 읽기 비교 규칙을 고칠 곳입니다.
   - Office 2007에서 PDF 내보내기는 'PDF/XPS로 저장' 추가 기능이 없으면 ENV-SKIP입니다 (오류 아님).
3. 눈으로 확인: 위 4단계 V1~V7, V9~V10 (V8 "파이썬 없는 PC"와 문서 보안 관련은 회사 PC에서).
4. Gemma 종합 테스트(3단계)는 사내 LLM이 필요해 집 PC에서는 하지 않습니다.

집 PC에서 확인할 수 없는 것 (회사 PC 몫): 문서 보안(DRM) 영향, Office 16 차트 전달 방식, Gemma의 요청 처리, 사내 OpenAI 호환 API 채점(`--judge`).
